## Authority ve consistent read

Authority state yokken legacy `user_data` salt okunur; pull bootstrap/backfill yapmaz. State varsa kayıtlar **tek** kaynaktır; zero active record bile `{}` verir, stale legacy fallback yapılmaz. Bir SQL statement state+rows veya absent-state legacy fallback döndürür; whole account tek SQL JSON aggregate satırına dönüştürülmez. Read schema/parse/storage hatası boş hesap sayılmaz. Missing migration (iki tablo da yok) legacy read'e izin verir; incomplete/unknown schema veya unsupported state version actionable 503 verir.

Wire pull `{data,syncVersion,updatedAt}` kalır. Capabilities auth gerektirir; ready/ACTIVE supported state için writable true, missing migration/unsupported schema/BLOCKED için false ve stable code verir. Bu genel storage yeteneğidir; bir payload'ın kayıpsız yazılacağını veya yeni restore workflow hazır olduğunu iddia etmez. Mevcut capabilities full consistent read kullanır; büyük paged export için lightweight state/page API sonraki tasarımda gerekir.

## Push transaction ve hesap kapısı

Request stream parse öncesinde byte limit ile okunur; Content-Length güvenilmez. syncVersion yalnız safe nonnegative integer; string/bool/null/float coercion yoktur. Pre-read yalnız compatibility/plan validation içindir. Gerçek karar **batch'in ilk SQL CAS statement'ıdır**.

Absent-state bootstrap `INSERT SELECT`, actual legacy version=expected ve user exists/deleted_at NULL koşullarını kontrol eder; existing-state `UPDATE WHERE revision=expected AND storage_schema_version=1 AND ACTIVE AND user exists/not deleted`. Başarılı revision expected+1, server unique write_token. Aynı batch'teki her json_each insert/update/tombstone authenticated user + new revision + bu token + version + state ACTIVE + user not deleted gate'ine bağlıdır. CAS zero ise kalan statement'lar no-op olur; success dönmez. SQL hatası bütün batch rollback yapar; disjoint committed chunk batch yoktur. Request response kaybı sonrası aynı base revision tekrar commit edemez; idempotency journal bu dilimde yoktur.

Byte/address/ordinal/content/state değişmeyen kayıtların modified revision'ı korunur; yeni kayıt created revision kazanır. Legacy bootstrap'ta surviving row'lar tek batch'te import olur; legacy'den silinen entity kayıtları durable tombstone olarak import olur. Deletion tombstone tutulur; eski cihaz güncel revision bilse bile aynı tuple yeniden yaratılamaz (`SYNC_RECORD_DELETED`). Açık restore/undo'nun tombstone politikası ayrı journal/root diliminde tasarlanmalıdır.

`BLOCKED` state gelecekte retention lifecycle için hook'tur. Current `users.deleted_at` ve physical deletion ikinci transaction gate'inde tekrar kontrol edilir. Pending/recovery/30-day scheduler burada uygulanmadı. Account hard delete önce hafif schema/account-version gate çalıştırır: iki yeni tablo yoksa legacy listeyle siler, ready ve supported state için eski+yeni tabloyu temizler, partial/unsupported schema/state halinde Apple revoke/OpenAI cleanup veya DB DELETE öncesinde 503 verir. Gate auth/confirm/password sonrası çalışır ve account data assembly yapmaz. Bakım script'i iki yeni tabloyu açıkça temizler; test FK on/off ile kanıtlar. Bakım script'i production'da çalıştırılmadı.
